# Phase 1 — THINK

## 1. Purpose

THINK transforms a raw idea, request, problem, or business need into a clearly defined project that is ready for solution design.

The purpose of this phase is to establish what should be built, why it should be built, who it is for, what it must accomplish, and what constraints must be respected.

THINK defines WHAT and WHY.

It does not define the detailed technical HOW. That responsibility belongs to Phase 2 — DESIGN.

---

## 2. Inputs

THINK may receive:

* User or client request
* Business problem
* Project idea
* Desired outcome
* User needs
* Existing website, software, or business system
* Existing code or project files
* Existing documentation
* Business processes
* User feedback
* Technical constraints
* Budget constraints
* Timeline constraints
* Platform or technology constraints
* Known requirements
* Known risks

Inputs may be incomplete or ambiguous.

Identifying missing information is part of the THINK process.

---

## 3. Process

### Step 1 — Understand

Determine:

* What is being requested?
* Who needs it?
* Why is it needed?
* What problem exists today?
* What outcome is desired?

### Step 2 — Clarify

Identify ambiguity, missing information, contradictions, and unanswered questions.

Do not silently invent missing requirements.

Unknown information must be identified as:

**UNKNOWN / NEEDS CONFIRMATION**

when appropriate.

### Step 3 — Define the Problem

Convert the initial request into a clear problem statement.

The problem should describe the actual need rather than prematurely prescribing a technical solution.

### Step 4 — Define the Desired Outcome

Describe what the project should accomplish when completed.

### Step 5 — Define Requirements

Identify and document:

* Functional requirements
* Non-functional requirements
* User requirements
* Business requirements
* Integration requirements, when known

### Step 6 — Define Scope

Clearly identify:

* In-scope items
* Out-of-scope items
* Known exclusions

### Step 7 — Identify Constraints

Document relevant constraints, including:

* Budget
* Timeline
* Technology
* Platform
* Resources
* Existing infrastructure
* Integrations
* Operational limitations

### Step 8 — Identify Assumptions

Record assumptions that are being made but have not yet been verified.

### Step 9 — Identify Risks

Identify potential risks that may affect:

* Scope
* Timeline
* Cost
* Technical feasibility
* Security
* Reliability
* User experience
* Project success

### Step 10 — Record Decisions

Record significant decisions made during THINK and the reasoning behind them when relevant.

### Step 11 — Define Success Criteria

Establish measurable or observable conditions that determine whether the project achieves its intended outcome.

### Step 12 — Prepare the Handoff

Organize the THINK artifacts into a complete handoff package for Phase 2 — DESIGN.

---

## 4. Recommended AI / Tools

### Primary AI — ChatGPT

Role:

**Strategist / Requirements Analyst**

ChatGPT may be used to:

* Analyze the problem
* Ask clarifying questions
* Identify missing information
* Challenge assumptions
* Identify contradictions
* Structure requirements
* Define scope
* Identify risks
* Compare high-level approaches
* Define success criteria
* Organize project information

AI-generated assumptions or recommendations must not be treated as confirmed project requirements without appropriate human confirmation.

### Other Tools

Other tools may be used when necessary to inspect existing project files, documentation, data, or systems.

The framework is tool-agnostic. AI tools are workers within the framework and may be replaced as better tools become available.

---

## 5. Required Outputs / Artifacts

THINK must produce the following artifacts:

* Project Brief
* Requirements
* Scope
* Success Criteria
* Assumptions
* Decisions
* Risks
* Open Questions

These artifacts form the THINK Handoff Package.

---

## 6. Completion Criteria

THINK is complete only when:

* [ ] The problem is clearly defined.
* [ ] The desired outcome is clear.
* [ ] Target users or stakeholders are identified.
* [ ] Functional requirements are documented.
* [ ] Non-functional requirements are documented when applicable.
* [ ] Scope is defined.
* [ ] Out-of-scope items are identified.
* [ ] Constraints are documented.
* [ ] Assumptions are documented.
* [ ] Risks are documented.
* [ ] Important decisions are recorded.
* [ ] Success criteria are defined.
* [ ] Open questions are resolved or explicitly accepted as unresolved.
* [ ] No critical ambiguity remains.
* [ ] Phase 2 has sufficient information to begin design.

A conversation with an AI does not constitute completion by itself.

Completion is determined by the required artifacts and completion criteria.

---

## 7. Handoff Requirements → Phase 2

Phase 2 — DESIGN must receive the complete THINK Handoff Package:

1. Project Brief
2. Requirements
3. Scope
4. Success Criteria
5. Assumptions
6. Decisions
7. Risks
8. Open Questions

The handoff must allow Phase 2 to understand:

* What is being built
* Why it is being built
* Who it is for
* What it must accomplish
* What is in scope
* What is out of scope
* What constraints must be respected
* What risks and uncertainties exist

Phase 2 should not need to reconstruct the project definition from the original AI conversation.

---

## Phase Boundary

THINK defines:

**WHAT + WHY**

THINK does not define the detailed technical:

**HOW**

Detailed architecture, technology selection, system structure, UX design, technical specifications, and implementation planning belong to Phase 2 — DESIGN.

---

## Phase Exit

THINK may proceed to Gate 1 only when all required completion criteria are satisfied.

**THINK → GATE 1 → DESIGN**
